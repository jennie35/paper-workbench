# 研序 Paper Workbench

一个按课题持续积累论文、精读证据和可检验研究行动的开源研究工作台。

用户通过浏览器操作，不需要安装软件。默认可在网页填写模型 API 地址与密钥，检索论文并依据实际取得的资料生成研究报告，也可添加参考 PDF 来界定研究范围。报告会标明资料覆盖；需要原图与公式视觉核验时，使用高级私人后台模式。项目不含真实私人课题、论文库、API 密钥或第三方 Norman 技能。

访问[在线网页与合成演示](https://jennie35.github.io/paper-workbench/)，或查看 [GitHub 源码](https://github.com/jennie35/paper-workbench)。已启动本机服务的电脑可打开[本机看板](http://127.0.0.1:8095/)；这个地址只连接当前电脑，不是公网后端。

## 直接在在线网页使用

打开[在线看板](https://jennie35.github.io/paper-workbench/)，选择默认的「API 直连」，填写供应商的 HTTPS API 基础地址、API 密钥和准确的文本模型名。可尝试获取供应商模型列表，也可手动填写模型名。DeepSeek 官方基础地址为 `https://api.deepseek.com`；模型名以当前供应商提供的列表为准，不由密钥自动选择。

密钥只保存在当前页面内存，刷新后需重新填写，不写入 IndexedDB、localStorage、Git 或导出文件。未绑定主目录时，课题、提取文本、题录、批次和报告是当前站点 IndexedDB 中的浏览器草稿。支持目录授权的浏览器可通过顶部「保存目录」选择唯一长期主目录，核对保存后以该目录为正式来源；网页不能获取绝对路径，也不能通过手填路径取得磁盘权限。两种保存方式均不自动同步到私人后台或其他设备。

浏览器不持久保存原始 PDF 或论文原图，只保存实际提取的文字、覆盖信息和文件指纹。点击模型提取研究范围时，才将有长度边界的参考文本发送给配置的模型服务。目录保存及研究配置详见[研究工作流](docs/RESEARCH.md)。

直连结合 Crossref 与 OpenAlex 的真实题录，尝试补充摘要及可公开获取的 PDF。取得匹配论文身份的 PDF 文字时生成全文文字报告，否则依据实际摘要生成摘要研究报告；两者均不可得时只保留题录及缺口。OpenAlex 或出版社拒绝浏览器访问时，页面记录来源错误并继续可用来源，不保证每批凑齐目标篇数。参考 PDF 仅界定范围，不占论文额度。浏览器模式不执行服务器端 Norman 技能，也不完成原图或公式视觉核验；报告标明实际覆盖。关闭浏览器后任务停止，可重新填写密钥后手动恢复检查点。供应商须允许浏览器跨域请求（CORS），兼容 API 格式不保证能够直连。详见[API 直连使用说明](docs/DIRECT.md)。

| 使用方式 | 数据与任务所在位置 | 阅读范围 |
| --- | --- | --- |
| API 直连（默认） | 已授权主目录，或未绑定前的浏览器草稿；模型请求直接发给配置的供应商 | 参考 PDF 界定范围；已取得的论文 PDF 文字或摘要生成研究报告，明确未核验项目 |
| 私人后台（高级） | 自部署后端、数据库与文件目录；关闭网页后任务继续 | PDF、全文、原页与外部技能核验，具备条件后可完成精读 |
| 合成示例 | 随静态网页提供的演示数据 | 不对应真实论文，不调用模型 |

## 已实现

- 配置科学问题、研究阶段、对象、资源与约束、中英文关键词、排除范围及默认篇数；两种模式均可添加参考 PDF，未知条件不自动补设。
- 首页提供课题入口与删除课题按钮；进入课题后直接查看报告，以批次编号区分来源，运行记录折叠保留。
- 按批次检索，默认 5 篇，可选 1–20 篇；Crossref 与 OpenAlex 提供候选，来源不可用时保留错误与缺额原因。
- 按课题相关性、发表状态和年份筛选；DOI、规范化标题、作者和版本关系去重。
- 私人后台的全文身份检查、来源映射、全文分段分析、原始页面视觉核验、结论修正和原生结构校验。
- 按十一节组织题录与阅读范围、总结、研究主线、分析者流程、分类研究设计、设计决策、图表公式、证据边界、精读位置、迁移启示与可检验行动；保留分析时的课题快照，资料缺失明确标注。
- 跨论文综合支持、冲突与判断变化，引用已有行动提出优先验证的 1–3 项；综合失败保留单篇报告，读取页面不自动重试模型。
- 「最近更新」「全部文献」「精选精读」「下一步研究」四个课题视图，以及按需生成的运行简报。
- 可选目录授权保存、主目录内暂存与指纹检查；检测到生成文件被手工修改时保留原件，不覆盖用户批注。
- 浏览器检查点及手动恢复；私人后台还支持补充正文 PDF、长期唯一编号与跨课题证据复用。
- 私人后台登录保护、加密模型配置、文件鉴权、HTTPS 下载与内部地址拦截；直连密钥仅留在当前页面内存。
- 研究记录导出；直连导出包含参考 PDF 提取文本，属于私人研究资料。私人后台支持 Markdown、JSON 和包含图片的离线 HTML 文献库导出。
- 无需后端即可浏览的合成示例；示例不调用模型，不冒充真实精读。

## 架构

```text
GitHub repository ── GitHub Actions ── GitHub Pages
                                            │
                                      user's browser
                                      /             \
                         API direct mode          private backend mode
                         │       │                  │ HTTPS + Bearer session
                    directory /  scholarly sources  FastAPI API
                    IDB drafts
                                 + model API       │        │
                                            PostgreSQL   Redis / RQ worker
                                                            │
                                        Crossref / OpenAlex / model API
                                                            │
                                      external Norman skill + native engine
                                                            │
                                                private persistent files
```

Pages 托管静态网页。直连模式由当前浏览器发送检索和模型请求，浏览器关闭后停止执行；私人后台模式由独立服务提供资料并执行任务，关闭网页不会取消后台任务。两种模式的课题库分别保存，不自动互相导入。

## 本地看示例

要在自己的电脑实际创建课题、上传和保存资料，可使用[本机使用方式](docs/LOCAL.md)：维护者启动 `python backend/run_local.py` 后，浏览器访问 `http://127.0.0.1:8095/`。此模式不需要 Redis 或 Docker；自动分析仍需配置模型接口。

首页只显示课题入口。点击「进入课题」后，可查看报告、资料覆盖和带编号的批次记录；报告中的核验标识以实际读取和检查的资料为准。「返回课题首页」可打开其他课题。详见[报告与批次阅读](docs/RESULTS.md)。

部署者可在仓库根目录运行以下命令预览界面，普通在线用户不需要执行：

```sh
python -m http.server 8080 --directory frontend
```

访问 `http://localhost:8080`。直接通过 `file://` 双击开发版首页可能受 ES Modules 限制；按需导出的离线 HTML，以及授权主目录内的离线看板，可以双击打开。离线页展示已保存成果，不能执行联网分析。

## 发布 GitHub Pages

1. 在自己的 GitHub 账号创建空仓库 `paper-workbench`，将本目录内容提交到 `main`。
2. 仓库 Settings → Pages → Source 选择 **GitHub Actions**。
3. 推送 `frontend/` 后，内置 Pages 工作流发布静态前端。
4. 打开工作流返回的 Pages 地址。所有资源使用相对路径，支持仓库子路径。
5. 打开网页后可直接配置模型 API；要使用全文模式，选择高级私人后台连接，填写自己的后端 HTTPS 地址和管理员口令。

只有 `frontend/` 会被 Pages 工作流上传。不要把 `.env`、私人数据或外部技能复制进去。后台代码推送 GitHub 只同步源码，不会自动部署后台服务。

## 部署后端

以下配置用于高级私人后台模式。详见 [部署与运维](docs/DEPLOYMENT.md)。需要 Docker Compose、一个 HTTPS 入口、模型 API、外部 Norman 技能及其原生运行环境。

**平台边界：当前外部 Norman 1.4.0 原生引擎支持 Windows/macOS，不包含 Linux 引擎。** Linux Docker 部署需连接本项目提供的原生引擎桥接服务。不能只挂载技能目录就假定 Linux 能执行 Windows EXE；没有有效引擎时，分析预检会失败。

```sh
cp .env.example .env
# 编辑 .env，设置随机口令、加密密钥、Pages origin 和外部技能路径/桥接服务。
docker compose up -d --build
```

网页登录后，在「连接与模型设置」填写模型基础地址、当前供应商的密钥、文本模型、视觉模型及可选 OpenAlex 密钥。「仅保存配置」不调用模型；可选的「保存并检查接口」会先保存当前表单，再实际调用文本与图像模型，可能产生 API 费用。开始分析批次时，后台会自动预检，无须先手动检查一次。

同一 API 来源下，密钥留空可保留原值；更换供应商地址后必须填写对应的新密钥。配置发生变化会撤销旧的接口检查状态。网页服务地址、模型 API 地址和 GitHub 仓库地址用途不同，请分别填写。

兼容接口必须支持 `/chat/completions`、`messages`、文本 JSON 回答和 PNG data URL 图像输入；不同供应商支持程度不同。没有图像能力不能完成精读额度。

## 研究流程与可信度

两种模式中，参考 PDF 默认界定研究范围，不占论文额度。直连每份 PDF 限制为 50 MB、300 页；同一课题的参考资料按 SHA-256 指纹去重。扫描件需要先做 OCR，加密 PDF 拒绝处理，部分无法提取文字的页面会显示缺口；本机文本提取不等于核验原图。检索优先近两年的候选，不足时扩展年份；没有可靠新论文时如实报告缺额。直连论文报告只依据实际取得且发送给模型的 PDF 文字或摘要，截断范围、页码及未核验内容随报告保存，不将文字报告计为完成原图与公式核验。

私人后台中的“已模型核验”表示模型读取了来源文本及选定原始页面，并通过结构校验，不表示独立人工复核或实验复现。文献、引用次数和发表状态不直接证明结论正确。摘要、下载链接和成功渲染都不等于完成精读；直连草稿没有这个完成标识。

私人后台中，同篇论文不重复作为新增：已有记录跨课题复用时明确提示，当前课题适用性仍需重新评估。无法取得全文的候选可在详情中补充 PDF，页面持续显示已保存状态。点击「继续整个批次」并确认后，后台处理本批剩余候选，沿用原批次范围与当前模型配置，可能产生 API 用量；正文替换会保留旧分析材料，不混用旧检查点。

后台全文模式的主要图表用原始整页图保留坐标、子图、图注与脚注。图像不清晰、必要补充资料缺失或模型报告未读内容时不标记完成。样本量、阈值无依据时必须留待先导实验确定。

## 开发与测试

前端测试需 Node.js 22.13 或更新版本；真实 PDF.js 文字核心测试使用合成 PDF，不依赖浏览器或画布渲染。浏览器 Worker、CSP 和文件选择界面仍需单独验收。

```sh
python -m venv .venv
# 激活虚拟环境后：
pip install -r backend/requirements-dev.txt
pytest backend/tests -q
node --check frontend/app.js
node --test frontend/tests/*.test.mjs
```

后端默认测试使用隔离的 SQLite 临时库与模拟模型，不需要密钥，也不会读取私人文献。生产后台使用 PostgreSQL 行锁和唯一约束；浏览器直连的存储、模型请求与恢复需单独验证。测试覆盖与未验证事项见 [验收记录](docs/VALIDATION.md)。

API 入口和数据接口见 [接口说明](docs/API.md)。通过 `/docs` 可查看运行实例的 OpenAPI 文档；数据操作仍需登录令牌。

课题配置、报告结构、跨论文综合和唯一主目录的完整约定见[研究工作流](docs/RESEARCH.md)。运行偏好不会创建定时任务；日常不自动生成 DOCX、ZIP 或 `outputs/work` 完整副本，汇报及备份按需导出。

原创代码采用 [MIT](LICENSE)。Temml 用于在浏览器本地将 LaTeX 转换为 MathML，其许可及字体通知保存在 `frontend/vendor/`。本地 PDF 文字提取使用 Mozilla PDF.js 6.4.299，采用 Apache-2.0；随包保留的 core-js、Adobe CMap 和字体分别遵守其原许可，详见 [PDF.js 依赖与许可通知](frontend/vendor/pdfjs/THIRD_PARTY_NOTICES.md)。后端 Python 依赖列于 `backend/requirements.txt`。

Norman Paper Reading 为后台全文模式的外部依赖，项目不复制、下载或重新许可其规则、工具和二进制。部署者自行提供合法可用的技能目录。后台完成的分析保留技能要求的双语署名；浏览器报告不声称已应用该技能。论文、原图及用户资料保留各自许可，不随项目代码改用 MIT；公开分享研究资料前应逐项检查许可与公开范围。

本项目面向个人使用，提供浏览器直连和单人私人部署，不提供公开注册、多人协作、自动定时分析或自动公开论文库。
