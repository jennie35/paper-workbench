# 阅读批次结果

首页只提供课题入口。先点击「进入课题」，在课题内的「文献与研究行动」「分析批次与结果」中查看对应资料；「返回课题首页」用于切换课题。

「批次结束」只表示本次流程已停止，不保证达到完整精读目标。课题内会单独列出目标、已登记精读、候选和缺额。例如目标 5、完成 0 时，页面显示「批次结束，仍缺 5 篇精读」。

已通过全文、原图与结构校验的论文进入正式文献库并取得连续编号。候选区单独保留待补全文、未核验草稿、待处理和排除记录，不把临时分析冒充完整成果。

- 在该课题的「文献与研究行动」中，使用「最近批次」选择批次；也可进入「分析批次与结果」，点击「查看文献、候选与草稿」。
- 候选区默认显示需要补证据的论文，优先显示已保存草稿；可切换为全部候选或查看排除理由。
- 点击「阅读分析草稿」，可阅读已有总结、研究设计、证据、行动建议及分段阅读记录。页面明确显示未核验状态和缺口。
- 原图页区分「文件已获取」和「已有页面核验记录」。取得图片不表示全文分析通过；没有编号图表的页面仍可打开查看原页。
- 「查看正文来源定位」显示抽取的来源块；「下载全文 PDF」和候选 JSON 导出均从私人后台获取，不会自动公开。
- 缺少正文时可补传可读取 PDF。上传成功后，页面持续显示「全文已保存，等待继续整个批次」及文件名；这不代表完成正文身份或图表核验。
- 点击「继续整个批次」后先查看确认信息。恢复会处理本批剩余候选，沿用原批次研究范围、使用当前模型设置，可能产生 API 用量；并非只分析当前打开的一篇。同篇论文不会重复登记。
- 正式文献库无记录时不导出空库；候选或草稿可在各自详情中单独导出 JSON，仍带未核验标识。

新课题、其他浏览器标签页的修改可用顶栏「刷新」同步。切换课题时会清除旧筛选条件，旧网络响应不会覆盖新课题的结果。一个实例同时只运行一个批次；已有任务时使用「查看运行中的批次」进入所属课题。

开始新批次时，后台先检查外部技能、文本与图像能力；预检失败会保留具体错误。HTTP 429 会区分已识别的 API 额度或消费上限、请求频率限制，以及供应商未返回可识别错误码的情况，按页面提示处理后再恢复。
